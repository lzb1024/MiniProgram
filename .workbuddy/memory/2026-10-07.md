# 2026-10-07综合版改造：首页变行程列表 + 长沙行程

## 做了什么
小程序从「单行程」改成「综合版」：新首页 `pages/index` 列出所有行程，点卡片进对应攻略。
第一版两趟：**川西**（9.25-10.03，9 天）与**长沙**（11.06-11.08，3 天 2 晚）。

## 结构

## 三个关键决定（都验过）
1. **端点按路径不按 query**：`/home/trip/chuanxi`、`/home/trip/changsha`、`/home/trips`。
   原因：WxMock 用**完整 URL 字符串**做 key（`Mock._mocked[config.url]`），
   带 `?trip=xx` 匹配不上，会直接走真request 然后 fail。
2. **三链按行程完全隔离**（用户选的）：`api/trip.js` 所有函数加 `tripId` 首参；
   本机 key `trip_packing_{id}`；云库三集合加 `tripId` 字段。
3. **老数据不用重导**：`filterByTrip()` 让**无 `tripId` 字段的老记录自动归`chuanxi`**（`DEFAULT_TRIP`）。
   默认行程读云库**不加 where**（加了老记录就全丢），改在内存里筛；非默认行程才严格 `where`。
   实测：5 条混合数据 → 川西读 3 条（含 2 条老数据）、长沙读 2 条，互不串。

## bash 的新坑
- 含 `cp` 的复合命令容易被沙箱决策层拦掉，报
  `sandbox-center cmd decisionRecord missing actual resource subject`；
  `/tmp` 下的写入也会被拦。**写文件优先用 Write 工具**，临时目录建在 `.workbuddy/` 下。
- `node` 不在 PATH，且**不能用 `_run.js` 套一层**（见上）。直接用绝对路径：
  `"C:/Users/Administrator/.workbuddy/binaries/node/versions/22.22.2-6/node.exe" xxx.mjs`
