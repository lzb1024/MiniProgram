## 修吸顶导航被右上角胶囊挡住（10:50）

用户：「顶部的花费统计和交通统计都被小程序的关闭按钮挡住了」——指吸顶条第一行章节的最后两项
（mock 里文案是「花费统计」「交通记录」，`sections` 第 6、7 项）。

### 根因
`.toc` 吸顶时 `padding-top = statusTop`，而 statusTop 原来只取 `statusBarHeight`（47px 左右）。
小程序右上角胶囊（「···」/「⊙」）浮在**状态栏下方同一条竖直带**里（iOS 约 51~83px），
章节行从 47px 起、高约 30px，正好整行落进胶囊范围 —— 左侧几项横向够不着胶囊所以看着正常，
末两项在 scroll-view 右端，恰好压在胶囊正下方，被整个盖住。

### 修法（三处）
| 文件 | 改了什么 |
| --- | --- |
| `pages/home/index.js` | 新增 `tocTopInset(statusBarHeight)`：用 `wx.getMenuButtonBoundingClientRect()` 取**胶囊下沿 + 与状态栏等宽的呼吸位**（`Math.max(rect.top - sbt, 4)`）；拿不到胶囊信息时兜底 `sbt + 44`（胶囊标准高度）。`onLoad` 改用它算 statusTop，并存 `this._tocTop` |
| `pages/home/index.js` | `onPageScroll` 的判定线从写死 `scrollTop + 140` 改成 `scrollTop + (this._tocTop \|\| 0) + 96`（96 = 两行内容高度，原来 44+96=140，逻辑等价但随平台自适应） |
| `components/nav/index.less` | `.nav` 的 `z-index` 20 → 31（高于 `.toc` 的 30） |

### 为什么必须动 nav 的 z-index
`margin-top: -statusTop` + `padding-top: statusTop` 是「静止时外观不变」的实现方式。
留白一加大，`.toc` 上移的量跟着变大，它那块垫底填充区（`__fill` 是**不透明** `@bg` 实色）
会向上顶进导航栏那一段、盖住搜索框。让 nav 的 z-index 高于 toc：静止时整块压在 toc 之上，
外观零变化；滚动后 nav 随页面滚走，填充区才露出来。

### 关键认知
- **吸顶条顶部留白必须越过胶囊，而不是只留状态栏** —— 这是小程序自定义导航的通用坑，
  与「页面有没有自定义导航栏」无关，胶囊永远浮在右上角。
- 该改动**不影响静止布局**：内容位置 = navH + padding - statusTop ≡ navH，与 statusTop 取值无关，
  所以调大留白不会推高页面。
- `scrollToId` 里的 `offset` 本来就是动态读 `.toc` 高度，自动适配，不用手改。

（`interface-preview.html` 320,821 B / 7 屏）、**test-weather 31 PASS / 0 FAIL**、

### 需求先问清了两处歧义
填写方式 → **纯自由文本**（不要预置 chips）；要不要能跳过去 → **要一键跳转**。
这两条合起来原本有矛盾：自由文本意味着渠道不固定，而跳转必须有目标。
解法靠调研敲定，见下。

### 关键调研（决定整个方案，别再回去找 appid）
查官方文档 `wx.navigateToMiniProgram`：
- **`appId` 不是必填**，传 `shortLink`（基础库 2.18.1+）即可跳；
- `shortLink` 就是用户在微信里对目标小程序点「… → 复制链接」拿到的
  **`#小程序://名称/页面/短码`**（名称夹在 `//` 与第一个 `/` 之间，解析靠这个）；
- 使用限制只剩「必须用户点击触发」（2.3.0+）与「跳转前微信统一弹确认框，取消 → `fail cancel`」；
  **`app.json` 的 `navigateToMiniProgramAppIdList` 已不是前置条件**；
- 开发者工具里调用**不会真跳**，但会校验这次调用是否合法，所以至少能半验。

⇒ 方案 = **一个输入框吃两种填法**：写名称（12306 / 携程 / 某小程序）就只当文字展示；
粘链接则名称被解析出来显示、原链接留下做跳转入口。**不需要维护 appid 映射表，也不需要用户改代码。**
解析收在 `api/trip.js` 的 `parseSource()`（`MP_LINK_RE`），页面与预览只认解析后的 `src` / `link` 两字段。
