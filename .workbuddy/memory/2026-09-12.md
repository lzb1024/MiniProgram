## 第六轮：天气接口可行性调研（用户问「天气能否调用腾讯小程序的接口」，只调研未动代码）

### 结论：能，但要用「腾讯位置服务」（微信本身没有开放的天气 API）
- 接口 `https://apis.map.qq.com/ws/weather/v1/`，GET。`key` 必填；
  `adcode` 或 `location=纬度,经度` 二选一；`type=now`(默认) / `future` / `hours`；
  `get_md` 仅 `type=future` 生效，`0`=当天+未来3天、`1`=当天+未来6天；
  `added_fields` = `alarm`(仅 now) / `index`(仅 future) / `air`。
- 返回：`type=now` → `result.realtime`；`type=future` → `result.forecast.infos[]`
  （`date / week / day{weather,temperature,wind_direction,wind_power,humidity} / night{...}`）。
- request 合法域名加 `https://apis.map.qq.com`（腾讯自有域名、已备案，**个人小程序也能配**，
  不必自己备案）。官方小程序 SDK `qqmap-wx-jssdk` 只是同一批 WebService 接口的封装，
  底层仍走 `wx.request` + 域名白名单，能力上限完全相同。
- Key 申请：腾讯位置服务控制台 → 创建应用 → 建 Key 时场景选「微信小程序」、勾 WebService API、绑 appid。

### 对本项目的硬约束（关键，别再重复踩）
1. **接口最长只有 7 天（当天 + 未来 6 天）**。行程 9.25-10.3 共 9 天：
   今天 9.12 能查到的最远是 9.18，**连出发日都不在窗口内**；要等 **9.19** 才查得到 9.25
   （9.19+6=9.25）。也就是说 9 天行程**永远无法一次全覆盖**。
   → 只适合做「首页顶部今天/明天一条实时天气」，**不能替代** `days[i].weather` 那两条逐日静态文案。
2. Key 硬编码在前端会被反编译拿到（SK 签名也救不了，SK 同样得下发）。项目 `cloudEnv` 仍为空串、
   `useCloud:false`，要走「云函数中转」须先开云开发（与 `api/trip.js` 的 wx.cloud 链路同源，顺路）。
3. 第四轮删掉的「实时天气汇总块」若要复活，建议放首页总览区，且只在出行日临近时出现。
4. 已向用户说过的口径：`daysDesc` 里产物写「当日天气为实时预报」改成「为参考预报，出发前请再核对一次」，
   若真接上接口，这句文案可以再改回去。

### 未动手
用户只问可行性，**没有改任何代码**。已给出三条路径（前端直连 / 云函数中转 / 维持静态）等用户选。

## 第十轮：定位 `chengdu:0/0` 的根因（真实 Key 已生效，卡在解析层）

### 用户 Console 两条日志
1. `[trip] 读取 costs 失败 ... errCode: -502003 database permission denied`
2. `[weather] 未取到数据 chengdu:0/0`

### 根因一（用户操作）：costs 集合权限没放开
`-502003` 就是集合安全规则没放行。用户只把 `packing` 改成了自定义安全规则，**漏了 `costs`**。
（`guides` 当前代码没在读，但一并配好更省事。）
→ 去控制台把 `costs` 也改成「自定义安全规则」填 `{"read": true, "write": true}`，照 `packing` 抄。

### 根因二（代码，已修）：`result.realtime` / `result.forecast` 是**数组**，不是对象
官方文档（`lbs.qq.com/service/webService/webServiceGuide/weatherinfo`）写得很明确：

| 字段 | 类型 | 嵌套 |
| --- | --- | --- |
| `result.realtime` | **array of object** | 内含 `infos` 是 **object**（单数） |
| `result.forecast` | **array of object** | 内含 `infos` 是 **array of object** |

`realtime` 和 `forecast` **都是数组**，而旧云函数代码写的是 `result.realtime.infos`，把数组当对象取属性 →
`undefined` → 解析落空。上游 `status` 却是 `0`（成功），于是只剩 `chengdu:0/0` 这种「成功但空」的日志。

**修法**：加 `unwrap(value)`（数组取 `[0]`，对象原样返回），`pickRealtime` / `pickForecast` 全部改走它。
`realtime.infos`（对象）与 `forecast.infos`（数组）两种形态因此都能吃下。

### 顺手加固：失败日志带上上游真实结构
新增 `shapeOf(res)`，解析失败时把 `result` 下的键名与类型一起打进 errors，
输出形如 `chengdu:0/0 result{realtime[1] forecast[1]}`。这样若上游哪天又改结构，
看一行日志就知道该认哪个字段，不用再来回猜。假 Key 场景实测输出 `chengdu:311/311 no-result no-result`。
