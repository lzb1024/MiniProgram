## 第三轮：修「编译 .wxss 文件错误」导致的白屏（同日下午）

用户导入微信开发者工具后截图反馈：模拟器页面全白，顶部提示
「编译 .wxss 文件错误，错误信息如上，可在控制台查看更详细信息」。

### 定位过程（关键）
没有靠猜，而是**直接读了开发者工具自己的源码**：
1. 解析开始菜单快捷方式（`.lnk` 里是 UTF-16 明文）拿到安装目录
   → `E:\Software\Tencent\微信web开发者工具`
2. 在 `resources/app.asar`（纯文本可搜）里搜报错常量，
   定位到 `COMPILE_WXSS_ERROR_CONSOLE`
3. 搜 `commonUseFilePath` / `summer-less`，读到 less 插件的真实实现：
   ```js
   // 除 app.less 外，每个 .less 前置注入一行
   n = `@import (optional, reference) '${relPath}/app.less';\n` + n;
   less().render(n, { paths: [], ... });   // ← paths 是空数组
   ```

### 根因
`@import '/variable.less'` **开头带斜杠**，LESS 会当成**文件系统绝对路径**
（Windows 上 = `C:\variable.less`），报 `'/variable.less' wasn't found`。
而开发者工具恰好传 `paths: []`，无法像 `paths: [项目根]` 那样兜住 → less 渲染抛错
→ 报「编译 .wxss 文件错误」→ app.wxss 没生成 → 全站白屏。

**这个坑是原模板自带的**：TDesign starter 里每个页面都写的
`@import '/variable.less'`。我把 app.less 也加上了同样的 import 后，
连 app.wxss 都挂了，所以是整屏白。

### 修复
9 处 import 全部改成相对路径：
- `app.less` → `@import './variable.less';`
- `components/*/index.less`、`pages/*/index.less` → `@import '../../variable.less';`

另外把全项目唯一的 `pages/search/index.wxss` 改名为 `index.less` 统一（插件
`resolveExt: {wxss:"less"}` 会把 `.wxss` 请求解析成 `.less`，孤立 `.wxss` 易踩坑）。
现在项目里没有任何 `.wxss`，样式文件全部 `.less`。

### 校验脚本的重大修正（教训）
原来的 `lesscheck.js` **传了 `paths: [ROOT]` 并加了 FileManager 兜底**，
甚至在注释里写明了"以 / 开头会被当成根路径而失败"却把它重定向掉 —— 这恰恰
**把真机必挂的错误掩盖成离线全绿**。已重写为忠实复刻：
`paths: []` + 前置注入 `@import (optional, reference) '<rel>/app.less'`，
并对绝对路径 import 输出修复提示。正反向都验证过：
- 正向：项目 11/11 OK
- 反向：故意放一个 `@import '/variable.less'` → 正确 FAIL 并提示

`build-preview.js` 同步改成 `paths: []`，并让编译失败时以非零码退出。

### 最终校验
| 检查项 | 结果 |
| --- | --- |
| LESS 编译（复刻 devtools 的 `paths: []`） | 11/11 OK |
| JSON 合法性 | 15/15 OK |

## 第四轮：改完 import 仍报同一错 —— 真因是「0 字节编译产物」（同日下午）

第三轮把 import 改成相对路径后，用户重新编译**仍报同一句**
「编译 .wxss 文件错误」。说明 import 路径不是唯一原因。

### 定位过程
继续读开发者工具的运行日志与源码：

1. 日志目录 `%LOCALAPPDATA%\微信开发者工具\User Data\<hash>\WeappLog\logs\`
   最新那份 → 每次失败都紧跟在
   `[CompileCache] call executor { cacheKey: 'miniProgramWxss', cacheSubKey: '__APP__' }`
   之后，**只有 `__APP__`（主包）失败，各分包页面全部正常**。
2. 在 `app.asar` 里搜到 `_wxssToJS` 的实现，关键两行：
   ```js
   const s = await t.getPackageWxssFiles(root || "__APP__");
   c.forEach(e => { n[e] = s.content[e] || "" });   // 缺内容补空串
   ```
   → **"编译产物为空"和"文件不存在"在工具眼里是同一件事**。
3. 又搜到 summer-less 的 `performLessLoad`：
   ```js
   if (!e.endsWith(".less")) return;             // 每个 .less 都会进这条流程
   ```
   → 确认工具会把项目里**每一个 `.less`** 都当成一个 wxss 来编译。
4. 辅证：日志里 `change variable.wxss`、`change app.wxss` —— 工具正是用
   `.wxss` 的名字在跟踪这些 `.less` 文件。
5. 直接实测：写脚本复刻工具语义（`paths: []` + 前置注入 app.less）逐个编译，
   打印产物字节数 → **11 个文件里只有 `variable.less` 是 0 字节**。

### 根因
`variable.less` 是纯令牌 + 混入文件，本身不产出任何 CSS 规则 → 编译产物 0 字节。
工具把 `variable.less` 当 `variable.wxss` 编进主包，产物为空即被判定为坏模块
→ 抛「编译 .wxss 文件错误」→ 主包 wxss 整体失败 → 全站白屏。
这也解释了现象**为什么只挂在 `__APP__` 上**：纯令牌文件在根目录，只进主包集合。

### 修复
给 `variable.less` 补一条极小的实体规则兜底，保证永远有产物：
```less
// ⚠️ 兜底规则，请勿删除（原因见注释）
.fg-tokens {
  color-scheme: dark;
}
```
修后逐个复验：`variable.less` 77 字节，**全项目 0 字节产物 = 0**。

### 顺带处置

# 第十一轮 · 把网页版的「所有流程和逻辑」搬进小程序

用户：「对应点击跳转呢，之前的html的所有流程和逻辑怎么都没了」

## 根因（最重要的一条）

首页内容被包在 `<t-pull-down-refresh>` 里，而这个 TDesign 组件**内部就是一个
`<scroll-view scroll-y>`**（`.t-pull-down-refresh{overflow:hidden;height:100%}`）。
→ **页面本身不滚动**，内容全在内层 scroll-view 里滚。
→ `wx.pageScrollTo({selector})` / `onPageScroll` / `position: sticky` **全部静默失效**。
这正是「点击跳转没了」的原因（不是没写跳转，是跳转不生效）。

**修法**：删掉 `t-pull-down-refresh`，改原生下拉刷新。
`pages/home/index.json` 加 `"enablePullDownRefresh": true` + `"backgroundTextStyle": "light"`
+ `"backgroundColor": "#0A0B1A"`；JS 用 `onPullDownRefresh` + `wx.stopPullDownRefresh()`。

## 这一轮做了什么

1. **mock/home/getTrip.js** 新增：
