## 本机网络诊断（供后续参考，别重复踩）
-环境注入 `https_proxy=http://127.0.0.1:55925`，这个代理**连不上 github.com**（502 / 000），git 走它必失败。
  但**直连 `api.github.com` 是通的**（需 `env -u https_proxy -u HTTPS_PROXY -u http_proxy -u HTTP_PROXY`）。
  结论：查仓库是否存在用 API 查，**别用 git/网页**，git push 只能用户本机来。
- 查仓库是否存在：`curl https://api.github.com/repos/<owner>/<repo>`；
  列公开库：`curl https://api.github.com/users/<owner>/repos?per_page=100`。
- **404 有歧义**：私有库对未认证请求也返回 404，看不出是「不存在」还是「私有」。
- 结论：`lzb1024/MiniProgram` 在 GitHub 上**查不到**（连用户公开库列表里都没有，只有 `glide`、`Screen` 两个），
  大概率还没在 GitHub 上建。remote 已指向它但**目标不存在**，首次 push 前得先建仓库。
- 实测有效的 SSL 兜底：`git -c http.sslBackend=openssl ls-remote`（本例报unexpected eof，换不出结果，
  但换 backend 这招在其他 TLS 环境下有用）。
