### 与网页版刻意的三处不同
1. **不灌假数据**：网页版空库时随机生成 10 条，会污染趋势判断；这里空就空，另给迁移 banner。
2. **趋势图不用 Chart.js**：小程序里引图表库太重，改成 canvas 2d 手绘，配色对着 `variable.less` 抄。
3. **导出/导入换成本机通道**：导出优先 `wx.shareFileMessage` 发文件，失败回落剪贴板；
   导入从剪贴板读 JSON（走同一条 `normalize`，所以网页版导出文件能直接粘进来）。

### 保留的网页版口径
- 统计口径：图表切到「全部」时，上方统计也跟着变历史（标签同步改「历史最高」等）
- 徽标：单条或整月等值时不打「最高/最低」
- 趋势阈值：每周 < -0.5 下降较快 / < -0.2 稳步下降 / < 0.2 保持稳定 / < 0.5 小幅上升 / 否则上升较快
- BMI：体重斤折公斤后再算，分档 18.5 / 24 / 28 / 35

## 当天第二轮：体重记录接入云数据库

用户问「这些数据是否存入了数据库」→ 此前只落本机，随即要求接入云库。

### 结构选择（关键决策）
**一人一份文档**，不是一条记录一个文档：
- `weight` 集合里只有 `weight_me` / `weight_ta` 两份文档，字段 `{ uid, records: [...], updatedAt }`；
- 理由：体重会攒到几百上千条，按条存的话「清空 / 导入历史」要发上百次请求，中途失败留半份脏数据；
  整份存一次读写完成，失败也不脏；两个人各写各的文档，互不覆盖；
- 代价：同一个人两台手机同时改会后写者胜（个人工具可接受）。

### 落地
- 新增 `api/weight.js`（CJS）：`loadLocal/saveLocal/backupLocal/fetchUsers/pushUser/pushAll/isCloudOn`
- `pages/weight/index.js`：先本机缓存出画面 → `syncCloud()` 拉云端覆盖；`persist()` = 本机落盘 + 异步推云；
  页头新增 `.wsync` 胶囊（已同步 / 仅本机 / 同步中）；`onShow` 里对上次推送失败的重试
- 迁移与保护：两份文档都不存在 → 把本机记录推上去（`migrated`），不让空云端吃掉本机；
  文档存在但为空（别处清空过）→ 以云端为准，覆盖前存 `weight_tracker_v2_bak`
- `config.js` 注释补 `weight` 集合与 `traffic`（原来只写了两个）；`pages/tools` 页脚改成
  「麻将与朱富贵只存本机，体重记录会同步云端」
- 新增 `.workbuddy/_selfcheck-weight-cloud.js`：假 wx + 假云库，跑迁移 / 覆盖 / 备份 /
  空数组 / 权限 -502003 回落 / set 不支持回落 add / 脏 records 共 30 条断言

### 校验
- `_selfcheck-weight-cloud.js`、`_selfcheck-weight.js` 全通过；lesscheck 9 个 less 0 失败；
  `_syntax-check.js` 20 个文件（含 api/weight.js）全通过

1. **id 撞车**：新记录用 `String(Date.now())` 当 id，同一毫秒连存两条会撞，

2. **跨风格 require**：`api/weight.js`（CJS）原来 `require('../../utils/cloud')`（ESM），
   这是本页唯一新增的跨模块风格依赖，也是最可能的加载期失败点。改成**不依赖 utils/cloud**：
   云环境本来就由 `app.js` onLaunch 按 `config.cloudEnv` 初始化，这里只探 `wx.cloud.database()`
   能不能拿到（探一次缓存结果，失败当不可用 → 回落本机）。两个自检脚本的假环境跟着改成
   `wx.cloud`，并加了「api 不该 require utils/cloud」的断言。

### 16:15 又一个真 bug：`isMissingDoc` 漏判真机文案（已修）
用户建好集合后报：
```
document.get:fail cannot find document with _id weight_me, please make sure that
the document exists and you have the corresponding access permission
```
`api/weight.js` 的 `isMissingDoc()` 只匹配 `DOCUMENT_NOT_FOUND` 和 `/not exist|doesn't exist|不存在/`，
而**这句话里只有 "exists"、没有 "not exist"** → 判不出来 → 异常冒到 `fetchUsers` 外层 catch →
明明云是通的却 `online:false`，页面显示「仅本机」。
修：显式加 `/cannot find document/i` 判定（保留前面 `collection` / `-502005` 的守卫，
否则集合没建会被当成「文档为空」→ 误触发反向迁移）。
回归用例加在 `_selfcheck-weight-cloud.js` ⑨b（两条：缺文档+本机空 → online true / 返回空；
缺文档+本机有货 → migrated true / 补写两份文档），跑完全绿。
**教训：云开发客户端 SDK 的「文档不存在」不是靠 errCode 判断的，必须认文案，且文案里没有 "not exist"。**

### 17:30 空白根因：canvas 不能放在带 CSS transform 的容器里
用户截图：伪横屏进去后**画布一片空白**，只有浮层文字在（说明 JS 跑到了、旋转也生效了）。
判定：**canvas 在带 transform 的祖先里不绘制**（WeChat WebView 的合成层问题）。
改法：**canvas 不再套 CSS transform**，改为在 canvas 自己的坐标系里转：
`ctx.setTransform(dpr,0,0,dpr,0,0)` → `ctx.translate(sw,0)` → `ctx.rotate(Math.PI/2)`，
逻辑坐标 (u,v) 映射到屏幕 (sw-v, u)，正好把「宽=屏幕高、高=屏幕宽」的横版图铺满竖屏。
位图尺寸直接用 `wx.getWindowInfo()` 的 sw/sh×dpr 算（**不靠 measurement**，
父层已经没有 transform，量不量都一样），节点拿不到时 `mountChart(n+1)` 每 50ms 重试，最多 12 次。
浮层文字（`我 · 全部时间 · 共 N 条` / `点任意处关闭`）**改成用 ctx.fillText 画进图里**，
避免再出现朝向错乱的 view。`chart.wxml` 现在只有一个 `<canvas>`，`chart.less` 只剩 2 条规则（617 字节）。
另外给 `onFullscreen` 加了 `_navLock` 短锁（只挡连点）+ `fail` 时退回 `redirectTo` 并 `console.error`
（用户报「返回后再点没作用」，此前 navigateTo 失败是静默的）。

### 17:35 图出来了，但又发现按方向的坑
换坐标系后 canvas 终于能画（**证实「canvas 在 transform 容器里不绘制」这个判断是对的**）。
但用户截图显示内容整体歪 90°：**当时模拟器/设备已经是横屏（windowWidth > windowHeight）**，
而代码无条件按"屏幕是竖的"去转，于是多转了一次。

- 已是横屏：**不转**，直接 `drawTrend({w:sw, h:sh})`。
探针加了两组断言（竖屏必须转、横屏必须不转 + 位图尺寸按各自方向算）。
顺手把「共 N 条」和「点任意处关闭」都改成左对齐、上下分开放，避免长短变化时撞在一起。
